# Solving Activation Problems

Solving activation problems requires a deeper understanding of
what motivates people to do things they do. A pretty good
model for behavior is Fogg’s model. We will start with Fogg’s
Behavior Model and then go into discovering levers that we can
use to change activation behavior.

# Fogg’s Behavior Model (FBM)

Fogg's behavior model states that for a behavior to happen, the
user should have the right ability, motivation, and
nudge/triggers. Triggers only work if either motivation or
ability is optimal.

# Motivators in FBM

```
The FBM contains three principal motivators: Sensation,
Anticipation, and Belonging. 
Sensation manifests in pleasure or pain. For example,
Gaming apps use vibrant graphics, compelling sounds, and
tactile feedback (like phone vibration) to provide sensory
pleasure, thus enhancing user motivation.
Anticipation manifests in feeling hope or fear. For
example, by dropping trailers and giving sneak-peeks into
upcoming series or seasons, OTT services build
anticipation and motivate users to stay subscribed.
Belonging manifests in social acceptance or rejection. For
example, fitness apps like Strava often have communities
where users can share their workout stats, join challenges,
and motivate each other, creating a sense of belonging.
As you look at the FBM graph, you will notice that high
motivation compensates for ability. Let’s take an example to
illustrate this point. A mother gets into a car accident, and her
child is pinned under the car. The motivation is incredibly high,
but the ability isn’t. However, at this moment, she lifts the car
off of the child. So motivation compensates for the low ability. 
That is why you can see triggers working even if ability is low
but motivation is high. 
```
```
Courses
```

Another thing to remember about motivation is that it's fickle,
and hard to sustain. That is also the reason why people start
exercising regularly at the start of any regime but leave after a
while when the motivation weans off. So treat motivation as a
fickle thing while building product experiences, and not a
continuous, sustained thing.

# Ability in FBM

```
The ability in the FBM can be of various types. 
Fogg considers five factors that constitute ability: 
Time : There is always an opportunity cost associated with
time. The more time a behavior is expected to take, the less
likely an individual is to do it
Money : Money is also a scarce resource for most people and
always has an opportunity cost. The more money is associated
with any given behavior, the less likely individuals usually are
to pursue it.
Physical effort : The body and mind are designed to preserve
our scarce calories. We tend to avoid physical effort in most
situations.
Mental effort : People naturally prefer to live on “autopilot”.
The more we have to think to do something, the less likely
people are to do it.
Non-routine : Routines are easy for us to adhere to. They
require less thought and motivation. The more we have to
deviate from set habits, the more effort it requires.

# Triggers in FBM

A trigger is a reminder to do something. 

```
Courses
There are three different triggers that we can use depending on
the situation: Facilitator, Signal, and Spark. When designing a
target behavior, the right type of triggers should be used. Let’s
go through the types real quick.
Sparks are triggers that provide a boost in motivation. For
example, a fitness app can use a lot of sparks such as an
inspirational quote in the notification to motivate users to go
for the workout session or run. 
Sparks are useful to initiate a behavior in individuals with
higher levels of ability, but lower levels of motivation.
Facilitators target individuals with high motivation, low ability.
An example of facilitators is adding voice search within a
shopping app. By adding local language, we make it easier to
use the app for locals. If a user left the app after downloading
because the local language wasn’t available, a notification
telling the user about it helps them come back to the app and
discover items they like.
```

# Guiding Users to an Action

```
While guiding the user on what to do, the product can choose
out of various options that exist. The forcefulness in guidance
design can vary. For example, in a music app, it can be less
forceful like showing them the tooltip on where to search
artists, or more forceful like asking them to make their first
search by blurring the rest of the screen.
Forcefulness is an important consideration while guiding a
user. High forcefulness asks users to do an action in a specific
way and limits the choice for the user, thereby making them
think less and reducing cognitive bias. 
Low forcefulness makes the action optional for the user, and
the guidance is generic. 
```
```
Language selection is an example which is highly forceful in
most apps because the number of options available are less and
can come on a screen.  The product doesn’t have to worry about
recommendation. It is also critical to the experience that comes
next because language is a key barrier to use apps.

# Activation Problems

```
To analyze and find activation problems, we need to invert the
problem and focus on what will prevent the aha! moment from
happening. The whole activation experience looks like a funnel
where we are taking users from setup → core action →
satisfaction aka aha! Moment.
To analyze activation, we can figure out both what part of the
activation funnel is broken, and why it’s broken.
A drop-off analysis between different parts of the funnel (setup,
supporting actions, core action, satisfaction) can provide you
insight into what part of the funnel is broken. We can further
do segmentation and cohort analysis on this funnel to further
narrow down which segments are affected most.
So to figure out where the funnel is broken, we need to
```
1. See where the drop-offs are high
2. See which segments or cohorts have the the higher drop-
    offs
But while data can tell us which part of the funnel is broken, it
can’t tell us why it’s broken. So we need to find ways to
understand why a particular part of the funnel may be broken.
To figure out why, we need to 
1. Use mental models like the Psych framework 
2. Conduct user research
Let’s cover the steps one-by-one.

# Segmentation and Cohort

# Analysis

In the activation stage, we don’t have much behavioral data of
the user. We have few days or couple of weeks of data because
these users are new in the system. So we have to do
segmentation on fixed attributes to figure out any patterns in
funnels. 

Some of the key segmentation attributes for a B2C product
could be:

1. Channels of acquisition
2. Product attributes like price, quality, etc.
3. Demographic 

```
Courses
```
4. Technographic
5. Geographic
In a B2B setup, Firmographic (size and type of firm in B2B) and
customer title becomes more relevant. 
Segmentation helps us figure out which fixed attributes
correlate high drop-offs. We can avoid such segments in
acquisition while we try to figure out the reasons for the drop-
offs.
We can also do cohort analysis to understand funnel behavior
over time.

```
Cohort analysis is the method to look at time-based cohorts
(say monthly) and figure out if there has been any change in
the funnel over time. For example, comparing Sep 2021
activation % to Sep 2022 activation % can tell us whether the
metric has dipped over the past year, stayed constant, or gone
up.
If we find a pattern in segmentation and cohort analysis, we can
delve deeper into understanding the ‘why’ further.
```

A pretty useful framework in analyzing activation funnels is the
Psych framework by Darious Contractor. The fundamental
construct is that every element on the screen adds or subtracts
emotional energy. For example, seeing a huge discount adds
energy, while getting a large form to fill reduces emotional
energy.

# Growth Levers of Retention

So far, our growth model has two inputs – new users and
retention.

Retention is necessary for sustainable growth in products. A
strong retention is an indicator of strong PMF. So how to
improve retention is one of the most important puzzles for a
product team.

To improve retention of the product, we need to stop focussing
on it directly and study inputs to the retention.

# Inputs to Retention

Here is how to think about it – Retention represents the
recurring value delivered to customers. To deliver value,

```
We need to get new users to experience the value of your
product as soon as they come to the product. This ensures
that they know what they value they can get from the
product, and hopefully come back again. 
We need to deliver value consistently for the user who is
coming back repeatedly. This can result in habit formation
around the product. Once the habit is formed, the users
will keep coming back themselves without any external
push.
Once the habit is formed, we have to make the habit
stronger and make sure they don’t move out of the
```
## You have already finished this chapter :)

```
Courses Log out
product.
If they move out of the product, we need to design
interventions to bring them back.
```
```
We can use terms to represent the various steps we mentioned
above.
Providing value to the first time user is Activation , since
we are activating the user on the platform. Activation has
multiple definitions in product literature. We will define it
as the user experiencing the core product value for the first
time. 
The initial period during which the habit isn’t formed fully
can be called Habit Formation period. Once the habit is
formed, users come back to the product automatically
when the need arises. Habit formation will lead to long-
term retention. 
The act of making the habit stronger by engaging users in
various ways is Engagement. Engagement refers to the
depth and frequency of the user interaction of the product.
Higher engagement generally leads to higher retention in
most cases. 
Managing the users from moving of the product is called
managing Churn. Resurrection refers to the user coming
back to the product due to an internal or external trigger. A
user coming back improves retention.
```
```
So the inputs to retention are:
```
1. Activation
2. Habit Formation
3. Engagement 
4. Churn
Retention is a function of activation, habit formation,
engagement, and resurrection.

# Core Action

The core action on a platform represents value delivery. 

In the case of transaction platforms, ordering followed by
delivery is the core action. In the case of productivity apps, the
core action is finishing tasks. In the case of an attention app,
it's getting the entertainment value and can be measured by
time spent.

# Supporting Actions

```
You would also observe that every core action requires few
supporting actions. For example, the supporting actions for a
transaction on an eCommerce app would be search, filters,
recommendations, etc. Without the
search/filter/recommendations, the user won’t be able to find
the product they need with ease, and so won’t perform the core
action. 
Building right supporting actions is important for optimal
conversion to core action. So how do we build the right
supporting actions in a product? We can think in terms of what
all would help in enabling core action. We can think of 4 things
in particular,
Awareness: First, the users need to be aware of what the
product promises, and how to use the product. While a
```
```
Courses
```

```
percentage of users who come to the product may know all
this information, we still need to think about how the
experience would look if a user doesn’t know about the
promise of the product and how to use the product.
Discovery: Step 2 is helping the user discover the right
solution. It is especially important where the catalog of
items sold is huge like in the eCommerce platforms. That's
why, Search and recommendations are two important
features to enable discovery in eCommerce platforms.
Motivation: Increasing the motivation for the user to
convert via social proof such as ratings and reviews, or
trust markers such as certification, improve the chances of
core action.  
Ability: Improving the ability for users in terms of time,
money, and effort required to perform the core action also
improves the chances of core action. For example, even if
the user is motivated to buy a high quality fridge, and
doesn't have the budget in that price range, they won’t be
able to buy it. But offering a large discount would improve
their ability to buy the fridge.
```
A good acronym to remember when thinking about the
supporting actions is ADMA – **A** wareness, **D** iscovery,
**M** otivation, and **A** bility.

# Aha! Moment

```
In the last step of activation, we ask the question whether the
user is satisfied with the core value delivered to them?  Delight
at the end of the experience is important in products since it
brings users back by creating a strong recall. It is also popularly
known as aha! moment. 
An important thing to remember about aha! moment is that it
is subjective and varies from user-to-user. 
Let’s take a food delivery app like Swiggy for example. Some
new users love the fact that they are getting food from their
favorite restaurants while sitting at home, whereas others love
that they discovered cheaper and better food on Swiggy. 
But while aha! moments may vary, it is important to measure
what % of users reached there, and we can measure it by
instrumenting certain mechanisms like user ratings on food
delivered in the product. That way, we can know whether the
```
```
Courses
```

user is satisfied with the core value or not, even if we don’t
know the exact reason what made them happy.

Another thing to remember is that even after doing everything
right and delivering value to the customer, a product may not
delight the customer. A user is always evaluating a product in
comparison to alternatives out there. For example, it could be
that when a loyal customer of Zomato orders from Swiggy, and
finds nothing extraordinary about Swiggy, it can dampen the
aha! moment.

In cases where delight can’t be measured accurately like in the
social media apps, we have to rely on supporting and core
action as a proxy for activation.

# Definition of the Activation

# Metric

In order to define the activation metric, we need to make it
time-bound so that we can accurately measure it, and also use
it to measure progress. 

But how do we define the time-boundary, aka T? There are
three methods of arriving at T, and we can use one or all of
these. 

```
Product usage data
Competition data
Natural frequency of the need
```
The first one is using product data to define T. Here, we can plot
a histogram of the time it takes for the user to complete core
action in the product. Here is a hypothetical data around what
% of Customer complete transaction within first n days (days
between Install and Transaction)

We can use the 75th or 90th percentile to define T as the
majority of users (75%, or 90%) complete core action within T.

The second method to arrive at T is competition-based. Here we

The third method is based on the natural frequency of the need

consumers order groceries at least once in a week, we can set
the T as 1 week for grocery ordering apps. The activation metric
then becomes the % of new users who order groceries within a
week of install. 
Be sure to employ both 1st and 3rd method for your product,
and pick the one that seems most reasonable.
